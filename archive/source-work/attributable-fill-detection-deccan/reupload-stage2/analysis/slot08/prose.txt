## What was wrong and what I changed

**`src/engine/fill_classifier.rs`** — how observations are read:

- `in_window` treated the window as closed at both ends. The end is exclusive, so an observation exactly at `start + ATTRIBUTION_WINDOW` names a recycled identifier, not this order.
- `absorb_event` **added** `cumulative_filled_qty` on every delivery. It is that order's running total, so it now raises a high-water mark — replayed, redelivered and out-of-order events no longer invent quantity.
- `absorb_block` had four defects: the eligible set ignored finalized orders (a finalized order contributes no outstanding quantity to a later block's basis); the ordering was `order_id` only rather than (window start, `venue_seq`, `order_id`); the truncation remainder went in a lump to the largest order instead of one unit each to the leading orders; and repeated ids in `covers` could double-count in the basis.
- `locate` resolved by `order_id` first. `client_ref` is now primary — it is the only key the engine always knows, and it is what distinguishes a recycled identifier from the original order. The `order_id` fallback remains, and the window test still guards it.
- Finalized orders no longer absorb direct fills (`venue-semantics.md`: a covered order never appears in `open_orders`, and a finalized order "will never acquire another base unit").

**`src/engine/cycle.rs`** — how derived quantities are computed:

- `close_gap` sized the corrective as `size - attributed`, ignoring quantity already working in committed neutralizations. It now uses the contract's residual: required − attributed − still working, where an acknowledged neutralization contributes its outstanding quantity, an unacknowledged one its **full size**, and a finalized one **nothing** (so its gap reopens and is corrected again).
- An unconfirmed leg — absent from `open_orders`, not cancelled by us — is now never neutralized against. A leg the venue closed by naming it in a block is a fourth state: known-closed, so its residual is corrected. A resting leg is still cancelled before any corrective is issued.
- A lost acknowledgement now keeps its record and is retried under the **same** `client_ref`; only `Rejected`/`Transport` drop it, leaving the exposure open to a later attempt.
- Added `retry_unconfirmed_legs`, so an entry leg the venue never acknowledged stays recoverable — by identity when an observation echoes its reference back, otherwise by resubmitting under it. Never under a fresh reference.

**`src/types/snapshot.rs`** — `Snapshot` gained `leg_attempts` (durable, with the original window start and the reference a retry depends on).

## One judgement call worth flagging

`tests/diagnostics.rs::a_later_block_divides_over_the_residuals_of_the_earlier_one` expected a **finalized** order to keep receiving shares from a later block. That contradicts `reconciliation-contract.md`: a finalized order "contributes no outstanding quantity to a later block's basis". The spec is declared the authority, so I followed it and rewrote that check into three tests that pin the underlying rule (basis is *current outstanding*, not size) and the finality rule separately. Similarly, I treat a block-closed leg as safe to neutralize rather than "unconfirmed", because the task brief's "a leg whose state is **momentarily** unknown is never neutralized against" describes a fill in flight — which a block provably precludes.
