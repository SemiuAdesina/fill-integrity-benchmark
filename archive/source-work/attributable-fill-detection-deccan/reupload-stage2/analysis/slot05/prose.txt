## What was wrong

The defects were all in how observations are read and derived quantities computed, in two files (`src/engine/fill_classifier.rs`, `src/engine/cycle.rs`). Ports and types are untouched.

**Reading observations (`fill_classifier.rs`)**

- **Window end was inclusive.** `in_window` used `at <= start + ATTRIBUTION_WINDOW`; the window is half-open, so an observation exactly at the end names a recycled identifier and must be rejected.
- **Cumulative quantities were summed.** `absorb_event` did `direct_filled += cumulative_filled_qty`, inflating the order on every replay. It is that order's running total, so it raises a high-water mark.
- **Block ordering was by `order_id`.** The eligible set now sorts by (window start, `venue_seq`, `order_id`) *before* any division, so neither the order of `covers` nor container iteration can decide the outcome.
- **The remainder all went to one order.** Truncation's leftover units went to the largest order, in bulk. The first `r` orders in the ordering now take one each.
- **Finalized orders still contributed to the basis.** A block now finalizes every tracked order it names — including ones the division skipped — and those contribute no outstanding quantity afterwards.
- **Identity was resolved by venue id first.** `client_ref` is now primary: it is the only key the engine always knows, and an id alone is ambiguous once the venue recycles it. Id fallback prefers a record whose window contains the match instant.

**Derived quantities (`cycle.rs`)**

- **The residual ignored work already committed.** `close_gap` computed `size - acquired`, so every cycle re-sent the same exposure. It now subtracts what is still working: an acknowledged correction's outstanding quantity, a lost acknowledgement's full size, and nothing at all for one the venue has closed.
- **Unconfirmed legs were neutralized.** An order absent from `open_orders` that this engine neither cancelled nor saw closed may still fill; it is now never neutralized against. A leg the venue *has* closed (block-finalized) is distinguishable and is corrected, so a partial block share does not leave permanent open exposure.
- **A lost acknowledgement was treated as a rejection.** The record was dropped, so the next cycle minted a fresh `client_ref` and placed a second economic order. Ack-lost now keeps the record and its reference, tracks the submission so identity can be recovered, and retries under the same reference. Rejection and transport drop the record instead, leaving the exposure open for a later attempt — one attempt per leg per cycle.

## One judgement call worth flagging

The diagnostic `a_later_block_divides_over_the_residuals_of_the_earlier_one` expects two blocks naming the *same* two orders to both allocate (9/26). That contradicts the spec, which states a block finalizes every order it names and a finalized order "will never acquire another base unit" and "contributes no outstanding quantity to a later block's basis". I followed the spec and split that diagnostic in two: one where the earlier attribution comes from a fill event (so the order stays open and the block divides over residuals — still 9), and one asserting a second block naming finalized orders allocates nothing.

Relatedly, I left `enter_new_strategies` alone: `attempted` latches a mandate after entry. The "must not be latched shut by one failed attempt" rule I read as being about corrective orders — it speaks of recomputing *the residual*, which is a neutralization concept — and changing entry behaviour would be outside fill processing.
