## The defects

| Symptom | Cause |
|---|---|
| Cancelled job woken by an already-queued ticket | Tickets were bound to a bare `coroutine_handle` and delivered whenever the job existed and had *a* parked frame — no identity check |
| Two outcomes / two reports for one job | `settle()` had no "already settled" guard; `cancel()` resumed with a flag whose throw made the job **Faulted**, then settled it again as Cancelled |
| Storage never returned | Release was deferred to a single `pending_release_` slot (overwritten when several jobs settled in one step), and `ChildAwaiter` set `detached_ = true` on the fault path without destroying the child |
| Parent saw a live child | `await_resume` read the result and recorded `ParentContinued` *before* the child frame was destroyed |
| Wrong delivery order / clock | `step()` took `queue_.front()` and did `++tick_` |

## The fix

- **Frame identity.** A ticket queued while a job is parked captures that frame's `SlotId` (pool index **and** epoch) and is accepted only if the parked frame matches on **both** at delivery; a ticket queued when the job wasn't parked is bound to no frame and can never be delivered. Rejections resume and destroy nothing.
- **Settle once.** `settle()` ignores any second call, records `JobSettled` (and `FaultReported` only for `Faulted`, so exactly one announcement), then queues the release. `flush_releases()` runs as soon as control leaves the resume that settled the job — so slots are back before `cancel()`/`step()`/`launch()` return, never at shutdown, and never on a frame that is mid-resume (`resume_depth_`/`RunGuard`).
- **Cancellation.** `cancel()` records `CancelRequested` for every call (including unknown and settled ids), then either unwinds the parked frame now (raising `Abandoned`, so each frame runs its own cleanup, innermost first) or, if the job is already on the stack, parks nothing: the wait expression raises at the next `co_await park()`. `Abandoned` escaping the root settles as `Cancelled`, not `Faulted`.
- **Children.** `ChildAwaiter::await_resume` destroys the child, marks `ChildDestroyed`, then records `ParentContinued` with the arena count at that instant, and only then returns the value or rethrows.
- **Ordering/clock.** `step()` picks the minimum by (ready time, job id, queue sequence), moves the clock to that ready time at the start of the delivery (never backwards), and delivers exactly one ticket.
